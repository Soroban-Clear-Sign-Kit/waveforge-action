# Refactor local-run harness to capture and assert structured GitHub Actions workflow commands

## Context
In `scripts/local-run.mjs` (lines 79-116), the local harness unsets `GITHUB_OUTPUT` so `@actions/core` falls back to legacy `::set-output` stdout lines and streams raw child output with `stdio: "inherit"`. Refactoring `scripts/local-run.mjs` to provide a temporary `GITHUB_OUTPUT` file and optional `--json` output mode allows developers and integration tests to inspect parsed multiline outputs (`score`, `suggested-complexity`, `report-json`) and `::error`/`::warning` annotations cleanly.

## Requirements
- Create a temporary `GITHUB_OUTPUT` file in `scripts/local-run.mjs` and parse `@actions/core` `ghadelimiter_<uuid>` key-value blocks after `dist/index.js` exits.
- Parse `::error` and `::warning` workflow commands (`file`, `line`, `title`, message) emitted by `src/repo-mode.ts` (lines 50-70).
- Print a structured summary of outputs, annotations, and `GITHUB_STEP_SUMMARY` at the end of `scripts/local-run.mjs`.
