# Cache Stellar RPC ledger verification responses across workflow steps

## Context
In `src/repo-mode.ts` (`runRepoMode` at lines 39-44), `runRepoChecks` is called without passing a custom `rpc` client in `RepoOptions` (documented in `upstream/waveforge-API.md` at lines 40 and 245 as `rpc?: RpcClientLike`). When a workflow runs `waveforge-action` multiple times or checks several identical deployed IDs across steps in the same job, caching `getLedgerEntries` responses in `RUNNER_TEMP` avoids redundant network RPC round-trips.

## Requirements
- Implement an optional file-backed `RpcClientLike` cache wrapper in `src/repo-mode.ts` keyed by network, RPC URL, and base64 XDR ledger key in `process.env.RUNNER_TEMP`.
- Allow `RepoModeDeps` in `src/repo-mode.ts` to inject an underlying `RpcClientLike` for deterministic offline unit testing.
- Pass the cached `rpc` client to `runRepoChecks` when available.

## Done when

- [ ] `RepoModeDeps` in `src/repo-mode.ts` accepts an optional `rpc` client and forwards cached lookups to `runRepoChecks`
- [ ] Unit tests in `src/repo-mode.test.ts` verify cache hits avoid duplicate `getLedgerEntries` calls using a mock `RpcClientLike`
