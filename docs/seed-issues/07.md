# Support pull_request mode to lint linked issues from PR descriptions

## Context
In `src/inputs.ts` (`Mode = "issue" | "repo"` at line 3 and `readInputs` at lines 19-23) and `src/index.ts` (lines 15-25), `waveforge-action` only supports `"issue"` and `"repo"` execution modes. Pull requests using `.github/pull_request_template.md` include a `Closes #<number>` reference, and adding a `"pull_request"` mode architecture lets repositories lint the linked issue automatically on PR events and report readiness before review.

## Requirements
- Extend `Mode` in `src/inputs.ts` and `action.yml` to accept `"pull_request"`.
- Implement `src/pr-mode.ts` (`runPullRequestMode`) to parse `Closes #<n>`, `Fixes #<n>`, or `Resolves #<n>` from `context.payload.pull_request?.body`, fetch the referenced issue via Octokit, and run `runIssueLint`.
- Route `inputs.mode === "pull_request"` in `src/index.ts` and write the lint report to `core.summary`.

## Done when
- [ ] `action.yml` and `src/inputs.ts` accept `"pull_request"` as a valid `mode` value
- [ ] `src/pr-mode.ts` parses closing issue references (`Closes #123`), fetches the linked issue via Octokit, and runs `runIssueLint`
- [ ] `src/pr-mode.ts` writes the Markdown report to `core.summary` and sets `score`, `suggested-complexity`, and `report-json` outputs
- [ ] `src/index.ts` routes `"pull_request"` mode and `dist/index.js` is rebuilt
- [ ] Unit tests in `src/pr-mode.test.ts` and `src/inputs.test.ts` cover missing PR payload, missing issue reference, and successful linked-issue linting
